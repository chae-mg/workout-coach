# 11단계 모바일 종합 검수

## 현재 상태

사용자 요청으로 남은 휴대폰 검수는 보류하고 12단계 GAS 파일 생성으로 넘어갔다. 이 단계는 부분 검수 후 종료 상태이며 아래 미확인 항목은 통과가 아니다. 보류 항목은 13단계 실제 배포 후 검수에 이관한다.

이후 13단계 실제 배포와 브라우저 기본 흐름 확인을 마쳤다. [실제 GAS 실행 주소·검증 결과](../05_DEVELOPMENT/GAS_DEPLOYMENT.md)를 참고한다. 이 문서의 사용자 확인은 앞선 로컬 미리보기 결과이며, 아래 휴대폰 미확인 항목을 실제 GAS에서 확인한 것으로 바꾸지 않는다.

로컬 자동 검증과 실기기 결과를 구분한다. 휴대폰의 작은 소리 문제를 반영해 음량·유지 시간을 늘렸고 사용자가 개선을 확인했다. 수동 종료까지 반복되는 휴식 알람도 10초 이상 지속과 끄기 후 다음 세트 진행을 정상 확인했다. 진동은 사용자 요청으로 제외했고 화면 꺼짐 방지는 문제없을 것으로 판단했다. 미확인 항목이 남아 있어 종합 검수 통과로 표시하지 않는다.

앱 전환 후 돌아왔을 때 현재 세트와 진행 상태가 유지되는 동작과 새로고침 후 이어하기로 같은 운동·세트에 복구되는 동작을 사용자가 정상 확인했다. 휴식 만료·시간 운동·화면 잠금·Chrome 종료 후 복구까지 확인한 것으로 확대하지 않는다.

휴대폰에서 공유한 HTTPS 미리보기 주소를 Chrome의 일반 탭으로 연다. 현재 주소는 이 PC의 `test-results/stage11/preview-url.txt`에 기록한다. PC와 서버·터널이 실행 중이어야 접속할 수 있다. 터널을 새로 만들면 주소가 바뀔 수 있고, 다른 주소의 브라우저 저장 데이터는 자동으로 옮겨지지 않는다.

현재 기존 임시 주소는 만료됐다. 새 외부 연결 생성은 자동 승인 검토에서 차단됐다. 같은 Wi-Fi에서 접속할 별도 로컬 주소 `http://192.168.68.54:4177`을 준비하고 PC에서 운동·반복 알람·종료를 검증했다. 휴대폰이 같은 Wi-Fi에 연결되어 있는지와 실제 접속 성공은 미확인이다. 현재 LAN 주소는 `test-results/stage11/lan-preview-url.txt`에 기록한다. 주소가 달라 기존 휴대폰 설정은 다시 지정해야 한다. HTTP 주소는 화면 꺼짐 방지 등의 HTTPS 필수 기능 검수에 사용하지 않는다.

공유는 [Cloudflare Quick Tunnel](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/do-more-with-tunnels/trycloudflare/)을 사용한다. 로그인 없이 공개된 임시 HTTPS 주소로 앱을 확인하는 방식이다. 로컬 서버는 앱 HTML·소스·이미지만 제공하며 저장된 개인 운동 데이터는 휴대폰의 localStorage에 남는다.

## 먼저 확인할 흐름

1. 설정에서 기본 세트 **2**, 기본 휴식 **5초**, 운동 간 휴식 **5초**를 입력한다. Tempo·휴식 종료음·종료 3초 카운트·화면 꺼짐 방지를 켜고 저장한다.
2. 홈에서 스쿼트 하나를 선택하고 오늘 운동을 확인한다. 오늘만 조정에서 Tempo를 **1-1-1**로 바꾸면 간격과 마지막 단계의 다른 소리를 쉽게 확인할 수 있다.
3. 운동 시작을 누른다. Tempo가 들리는지, 안내음을 끄면 멈추고 다시 켜면 재생되는지 확인한다. 필요하면 표시된 안내음 활성화 버튼을 누른다.
4. 세트 완료를 누른다. 5초 휴식에서 마지막 3초 안내와 휴식 종료 알람을 확인한다. 알람은 두 신호씩 반복하며 `휴식 알람 끄기`를 누를 때까지 다음 세트와 Tempo가 대기해야 한다. 끈 뒤 2번째 세트를 완료하면 추가 휴식 없이 전체 완료되어야 한다.
5. 완료 결과가 수행 **2**, 건너뜀 **0**인지 확인한다. 완료 버튼으로 홈에 돌아간 뒤 새로고침해 설정이 유지되는지 확인한다.

실제 횟수를 수행하지 않아도 조작으로 흐름을 검수할 수 있다. 소리가 나지 않으면 안내 문구와 휴대폰 미디어 음량 상태도 결과에 적는다. 기기 API 성공 여부는 모의 API 호출 기록으로 대신 판단하지 않는다.

## 결과 기록

휴대폰 기종·Android 버전·Chrome 버전, 검수 주소·시각을 적는다. 항목마다 통과·문제 있음·미실행·미지원을 구분한다. 문제가 있으면 직전 조작, 기대 결과와 실제 표시·소리를 함께 적는다. 일부 항목 성공만으로 나머지 항목을 통과로 기록하지 않는다.

| 환경·항목 | 기록 |
| --- | --- |
| 휴대폰·Android·Chrome | 미확인 |
| 검수 주소·시각 | 미확인 |
| 먼저 확인할 흐름 | 음량 조정 후 소리가 많이 커졌다고 확인함. 반복 알람 구현 후 소리도 잘 나는 것 같다고 확인함. 10초 이상 알람 지속과 끄기 후 다음 세트 진행을 확인함. 화면 꺼짐 방지는 문제없을 것으로 판단함 |
| 문제 재현·후속 수정 | 출력 수준·유지 시간 증가와 수동 종료까지 반복하는 알람 구현 완료. 진동은 사용자 요청으로 제품 범위에서 제외함. 화면 꺼짐 방지는 사용자 판단상 문제없음으로 기록하며 장시간·OFF 비교는 미실행 |

## 로컬 자동 검증

앞선 로컬 종합 검증 결과는 핵심 로직 **55개**, 기존 로컬 종합 시나리오 **12개**, 추가 화면·전체 흐름 **15개** 통과다. 가로 화면의 카드 가림 문제를 수정했다. 이후 휴대폰에서 발견한 소리 문제는 수정 후 관련 검증과 실기기 재검수를 진행한다.

`pnpm test:mobile`은 GAS 테스트를 제외한 핵심 로직, 기존 로컬 종합 시나리오, 360×800·390×844·412×915·844×390·1280×900에서 1개·초기 8개·반복과 시간 운동 혼합 구성의 전체 흐름을 검사한다. 별도 서버와 격리된 저장소를 사용한다.

추가 화면 검증은 시각을 제어한 Edge 헤드리스이며 작은 화면·가로 화면에서는 터치 입력을 사용한다. 물리적 Android 기기·키보드·브라우저 종료·가청·화면 꺼짐을 재현하는 검수는 아니다. 진동은 제품 범위에서 제외했다. 결과·PNG는 `test-results/stage11/`과 기존 `test-results/local/`에 저장한다.
