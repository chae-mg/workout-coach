# Workout Coach 단계별 개발 계획

## 목표와 진행 방식

개인용 Workout Player를 로컬에서 실행·테스트할 수 있게 만들고, 모바일 검수 후 같은 코드를 GAS 배포 형태로 전환한다.

한 번의 작업에서는 현재 단계 하나를 다룬다. 시작할 때 목표와 변경 범위를 공유하고, 끝날 때 결과·관련 검증·남은 항목을 보고한다. 사용자 피드백을 반영한 뒤 다음 단계의 범위를 정하며 여러 단계를 자동으로 이어서 구현하지 않는다. 현재 기능에 필요한 최소 연결 작업이 생기면 그 이유와 범위를 설명한다.

사용자가 특정 단계들을 함께 요청하면 그 범위만 묶어 진행한다. 5·6단계, 7·8단계, 9·10단계는 각각 사용자의 요청으로 함께 검토했으며 이후 단계를 자동으로 이어가지 않는다.

기존 코드는 앞선 작업에서 만든 구현 초안으로 보존한다. 각 단계에서 문서와 대조해 재사용하고 필요한 부분만 수정한다. 단계별 검토를 위해 기존 기능을 일괄 삭제하거나 별도 앱을 새로 만들지는 않는다. 앞선 테스트 통과 기록은 참고 자료이며 요구사항 검토나 실기기 확인을 대신하지 않는다.

## 현재 진행 위치

- **완료: 0~10단계의 구현·기술 검증.** 9·10단계는 실제 AudioContext의 재생 예약과 모의 기기 API의 요청·해제·실패를 검증하고 오디오 재활성화·아이콘 형식 표시를 수정했다. 진동은 사용자 요청으로 제품 범위에서 제외했다.
- **부분 검수 후 종료: 11단계.** 소리·10초 이상 반복 알람·수동 종료 후 다음 세트 진행·앱 전환 후 진행 유지·새로고침 후 이어하기는 사용자 정상 확인을 받았다. 진동은 제외했다. 사용자가 남은 검수를 보류하고 다음 단계 진행을 요청했다. [MOBILE_QA.md](../07_STATUS/MOBILE_QA.md)의 미확인 항목을 통과로 바꾸지 않고 13단계 배포 후 검수에 넘긴다.
- **완료: 12단계 — GAS 파일 생성·로컬 검증.** 최신 원본으로 파일 5개를 생성하고 진입점·HTML 조합·manifest·이미지 포함을 검증했다. 생성물 검증 1개와 동일 클라이언트의 브라우저 시나리오 12개가 통과했다.
- **배포·기본 검증 완료: 13단계.** 지정한 Apps Script 프로젝트에 파일 5개를 적용하고 버전 4를 본인 계정 전용으로 배포했다. 실제 주소에서 설정 저장·새로고침·이어하기·반복 운동·알람 확인·전체 완료와 테마 즉시 전환을 검증했다. 소리 증폭과 다크·라이트 모드 변경은 후속 배포로 반영했다. 상세 휴대폰 검수는 사용자 요청으로 보류한 상태다.
- 배포 주소와 실행 결과는 [GAS_DEPLOYMENT.md](../05_DEVELOPMENT/GAS_DEPLOYMENT.md), [WORKLOG.md](../07_STATUS/WORKLOG.md)에 기록한다. 로컬에서 받은 사용자 확인을 실제 GAS 환경의 실기기 통과로 확대하지 않는다.

## 후속 확인 — 배포 후 보류 항목

**읽을 문서:** GAS_DEPLOYMENT, WORKLOG의 12단계 결과, MOBILE_QA의 보류 항목.

**주요 파일:** `dist/gas/`의 생성 파일 5개와 대상 Apps Script 프로젝트의 기존 파일·설정.

**진행 순서:**

1. 실제 실행 주소에서 같은 Google 계정으로 접속한다.
2. 확인을 재개할 때 GAS의 소리·화면 꺼짐 방지·잠금·Chrome 종료·아이콘과 11단계 보류 항목을 검수한다.
3. 문제를 수정할 때 원본을 변경하고 GAS 생성물 검증 후 기존 배포를 새 버전으로 갱신한다.
4. 미확인·미지원·문제 항목을 구분해 결과를 기록한다.

GAS 전환·배포는 12·13단계에서 다룬다. 소리를 실제로 듣지 못한 검증이나 모의 기기 API 성공을 실기기 검수 완료로 표시하지 않는다.

## 단계별 검증과 완료 보고

현재 기능에 관련된 기존 테스트를 우선 사용하고, 동작을 바꿨거나 확인이 부족한 경우 필요한 검증만 추가한다. 초기 단계부터 전체 브라우저 시나리오와 GAS 빌드를 반복하지 않는다. 단계 5의 기본 흐름, 단계 8의 복구, 단계 11의 전체 검수, 단계 12의 변환에서는 영향 범위에 맞춰 통합 검증한다.

완료 보고에는 현재 단계와 범위, 실제 변경 파일·화면, 검증과 결과, 남은 문제, 다음 단계의 범위를 적는다. 구현 여부·자동 테스트 통과·사용자 피드백 반영·실기기 검수를 서로 구분한다.
