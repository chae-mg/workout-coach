# Workout Coach 작업 기록

## GitHub Pages로 기본 배포 전환 준비 — 2026-09-23

- 사용자가 GAS 대신 GitHub에서 프로젝트를 사용하고 싶다는 요청에 따라 정적 브라우저 앱을 기본 배포 대상으로 전환한다. GitHub 저장소는 이미 공개되어 있으며 로컬 앱 코드는 아직 원격에 반영되지 않은 상태였다.
- `.github/workflows/deploy-pages.yml`을 추가해 `apps/web/`만 GitHub Pages에 게시하도록 했다. 앱은 상대 경로 기반 ES 모듈이라 별도 번들 작업을 넣지 않았다.
- README, 제품·아키텍처·개발·현재 상태 문서를 Pages 중심으로 갱신하고 배포·저장 경계를 별도 문서와 ADR에 남겼다. 기존 GAS v4 배포는 보존하고 선택 가능한 이전 경로로 설명한다.
- GAS URL과 Pages URL은 다른 출처여서 `localStorage` 설정·세션이 자동 복사되지 않는 점을 명시했다.
- 커밋 `2ed570d`를 `main`에 푸시했다. Pages 자동 배포 작업도 시작됐지만 `Configure GitHub Pages` 단계에서 저장소에 Pages 사이트가 아직 설정되지 않아 실패했다. 워크플로 파일은 `GITHUB_TOKEN`으로 Pages 사이트를 임의 생성하지 않도록 두었다.
- 공개 주소 확인 전이며 남은 설정·재실행은 [`NEXT.md`](NEXT.md)에 기록했다. 코드 업로드는 완료됐고 실제 Pages 게시 상태와 구분한다.
- 검증: 로컬 Edge 브라우저 시나리오 12개와 핵심 로직 테스트 65개가 통과했다. `pnpm test`의 나머지 GAS 번들 테스트 1개는 샌드박스의 상위 디렉터리 접근 거부로 빌드하지 못했다. 이 GitHub Pages 변경과 직접 관련이 없는 기존 GAS 테스트다.

### 첫 GitHub Pages 게시 — 2026-09-23

- 사용자 승인 후 저장소 Settings → Pages의 게시 원본을 `GitHub Actions`로 변경했다.
- 실패했던 배포 작업을 재실행해 성공을 확인했다. `Configure GitHub Pages`, `Upload browser app`, `Deploy site`가 모두 통과했다.
- `https://chae-mg.github.io/workout-coach/`를 열어 Workout Coach 제목, 운동 선택 안내와 운동 카드 10개가 표시되는 것을 확인했다. 이는 실제 웹 배포 확인이며 Android 실기기 기능 검수는 포함하지 않는다.
- 기존 GAS 배포는 삭제하거나 수정하지 않았다. GAS 주소와 Pages 주소의 `localStorage`는 분리되어 있다.

## 최신 변경 — 레포 구조 정리

- 노션의 레포·문서 구조 템플릿을 기준으로 `apps/web/`에 웹앱 원본(`src/`, `public/`, `index.html`)을 모았다.
- 제품·아키텍처·디자인·개발·상태 문서를 `docs/01_PRODUCT`부터 `docs/07_STATUS`까지 분류하고 `docs/00_INDEX.md`를 추가했다.
- 루트 `AGENTS.md`, `apps/web/package.json`, 구조·현재 상태·다음 작업 문서를 추가했다. 앱이 하나뿐이므로 `packages/`는 만들지 않았다.
- 기존 루트 명령을 유지하면서 import·서버·GAS 빌드 경로를 갱신했다. `pnpm test`, `pnpm test:rest-settings`, `pnpm test:effects`, `pnpm test:gas`가 통과했다.

## 최신 변경 — 테마 즉시 적용 보완

- 화면 테마를 선택하는 순간 다크·라이트 색상이 즉시 바뀌도록 이벤트 연결을 보완했다. 저장하면 선택한 테마가 `workout_settings`에 유지된다.
- 로컬 단위 테스트 66개, 설정·브라우저 시나리오 12개, GAS 번들 검증을 통과했다. 실제 GAS 주소에서도 저장 전 즉시 라이트 전환과 저장·새로고침 후 유지, 다크 테마 복원을 확인했다.
- 같은 웹 앱을 버전 4(`Workout Coach v4 — 테마 즉시 적용`)로 배포했다. 웹 앱 주소와 접근 권한은 유지된다.

## 최신 변경 — 다크·라이트 모드 추가

- 설정의 `화면 테마`에서 다크 모드와 라이트 모드를 선택하도록 추가했다. 선택값은 기존 `workout_settings`에 저장되며 이전 저장값은 다크 모드로 안전하게 처리한다. CSS 변수와 브라우저 `theme-color`도 함께 바뀐다.
- 로컬 전체 테스트 66개, 설정·브라우저 시나리오, GAS 번들 검증을 통과했다. 라이트 모드 설정 화면을 시각 확인했다.
- 실제 GAS 주소에서 라이트 모드 저장·적용을 확인한 뒤 테스트 설정을 다크 모드로 복구했다. 같은 웹 앱을 버전 3(`Workout Coach v3 — 다크·라이트 모드 추가`)으로 배포했다. 이후 선택 즉시 적용 보완을 버전 4로 반영했다.

## 이전 변경 — 소리 크기 추가 조정

- 사용자 피드백에 따라 Tempo·카운트·휴식 종료 알람의 Web Audio 레벨을 기존 값의 약 2배로 올렸다. 각 신호의 peak는 `0.8`·`0.9`·`1.0`으로 제한해 디지털 클리핑을 피하도록 했다.
- 로컬 효과 테스트에서 증폭된 레벨·유지·페이드아웃을 확인한 뒤 GAS 번들을 다시 생성하고 같은 웹 앱의 버전 2로 배포했다. 배포 성공 표시와 실제 GAS 주소의 앱 로딩을 확인했다.
- 사용자가 버전 2를 휴대폰에서 다시 확인한 뒤 소리가 아주 좋다고 확인했다. 소리 크기 개선은 사용자 검수까지 완료한 것으로 기록한다.

## 현재 진행 위치 — 13단계 실제 GAS 배포·기본 검증 완료

### 13단계 후속 음량 조정 배포

- 사용자 요청으로 Tempo·카운트·휴식 종료 알람의 출력 레벨을 약 2배로 조정했다. 로컬 `pnpm test:effects`와 `pnpm test:gas`를 통과했다.
- 기존 배포를 버전 2(`Workout Coach v2 — 소리 크기 2배 조정`)로 업데이트했다. 웹 앱 주소와 접근 권한은 유지된다. 실제 휴대폰에서 다시 들어 체감 음량을 확인해야 한다.

### 13단계 실제 Apps Script 적용과 배포

- 대상: 사용자가 연 `Workout Coach` 프로젝트에 적용했다. [프로젝트 편집기](https://script.google.com/home/projects/1rec7mwX0oM_M91fwJOlWiEbZniOprCf7-QYEkiGGCcbMASqTQ_X5wtul/edit). 기존 파일은 기본 `Code.gs`와 manifest였으며 기존 내용은 `test-results/gas-deployment/before/`에 백업했다.
- 적용: `Code.gs`, `Index.html`, `Styles.html`, `Script.html`, `appsscript.json`을 저장했다. HTML·CSS·클라이언트·manifest를 편집기에서 복사해 줄바꿈 차이를 제외하고 입력 원본과 일치하는지 확인했다. 시간대 Asia/Seoul·V8·예외 로그 설정을 적용했다.
- 배포: 버전 1, 설명 `Workout Coach v1 — 반복 휴식 알람 포함`, 실행 계정은 본인, 액세스는 `나만`이다. Google 편집기의 배포 성공 표시와 실제 앱 로딩을 확인했다. 이후 버전 2·3으로 같은 배포를 갱신했다. [실행 주소](https://script.google.com/macros/s/AKfycbzU4_zMH3zNkuNn6uM7SMWpQu14PNVdIMCM883v7VMGXEIsyrEtWmE5EKPLTd7g7Jbq1w/exec).
- 실제 주소 검증: GAS의 두 iframe 안에서 설정 저장·새로고침 후 값 유지·운동 선택·시작·새로고침 후 같은 운동/세트 이어하기·휴식 종료 확인 화면·알람 확인 전 완료 조작 대기·확인 후 다음 세트·전체 완료를 검증했다. 스쿼트 2세트의 완료 결과는 수행 2·건너뜀 0이다. 안내음 활성화 상태를 화면에서 확인했으며 기기에서 들리는 소리를 직접 확인한 것은 아니다.
- 검수 데이터 정리: 테스트 세션은 완료 버튼으로 종료했고 기본 세트/휴식의 빈 값과 운동 간 휴식 120초를 원래 값으로 복구했다. 실제 개인 운동 기록을 삭제하지 않았다.
- 빌드 보완: 클라이언트 번들을 UTF-8로 압축했다. 미리보기 삽입 시 치환 문자열의 `$` 기호가 해석될 수 있는 문제를 생성물 일치 테스트로 발견해 콜백 치환으로 수정했다. `pnpm test:gas`의 생성물 검증 1개와 번들 브라우저 시나리오 12개가 다시 통과했다.
- 남은 제약: 사용자가 보류한 휴대폰 상세 검수 중 화면 꺼짐 방지·잠금/시간 운동/Chrome 종료·홈 화면 아이콘은 미확인이다. 배포와 기본 검증 완료를 종합 실기기 검수 통과로 확대하지 않는다. 로컬 미리보기의 설정·세션은 GAS 주소로 자동 이전되지 않는다.

### 12단계 GAS 파일 생성과 검증

- 진행 범위: 사용자가 추가 실기기 확인을 보류하고 다음 단계 진행을 요청했다. 11단계는 부분 검수 후 종료하며 미확인 결과는 그대로 남겨 13단계 실제 배포 후 검수에 이관한다.
- 산출물: 최신 원본에서 `dist/gas/Code.gs`, `Index.html`, `Styles.html`, `Script.html`, `appsscript.json`과 `dist/preview/index.html`을 생성했다. 운동 데이터·샘플 SVG·클라이언트 모듈을 포함하며 별도 Node 서버를 GAS에 설치하지 않는다.
- 검증 명령: `pnpm test:gas`에 생성물 검증과 브라우저 검증을 함께 연결했다. Windows에서는 별도 Playwright Chromium 설치가 없어도 설치된 Edge를 기본으로 사용하며 환경 변수로 채널을 지정할 수 있다.
- 생성물 검증: 파일 5개·서버 및 클라이언트 구문·이미지 포함·V8·Asia/Seoul·viewport·base를 확인했다. 모의 HtmlService에서 생성된 진입점을 실행해 include 파일 조합이 미리보기 HTML과 일치하는 것도 확인했다. 실제 Google 서버 실행은 아니다.
- 브라우저 검증: 생성물 검증 1개와 GAS 번들 미리보기의 기존 시나리오 12개가 통과했다. 운동 선택부터 완료·시간 운동·설정·복구·알람 종료·미지원·저장 실패·다섯 화면 크기를 검증했고 JavaScript·HTTP 오류가 없었다. 번들 미리보기는 `/` 외 로컬 JS·CSS·이미지 요청이 없었다. PNG 15개는 `test-results/gas/`에 기록했다.
- 당시 상태: 12단계에서는 Apps Script 업로드·프로젝트 생성·배포를 하지 않았다. 이후 13단계에서 사용자가 지정한 프로젝트에 적용·배포했다. 실제 모바일 동작과 11단계 보류 항목은 미확인으로 유지한다.

## 앞선 11단계 — 부분 검수 후 종료

### 반복 휴식 알람 구현과 검수

- 실기기 복귀 확인: 사용자가 다른 앱으로 전환한 뒤 돌아와 현재 세트와 진행 상태가 유지되는 것과 새로고침 후 이어하기로 같은 운동·세트에 복구되는 것을 정상 확인했다. 휴식 만료·시간 운동·잠금·Chrome 종료의 복구 결과로 확대하지 않는다.
- 사용자 확인: 음량 조정 후 소리가 많이 커졌다는 답변을 받았다. 이어서 휴식 종료 알람을 직접 끌 때까지 반복하도록 요청해 구현했다. 이후 “소리도 잘 나는 것 같다”는 추가 확인과 함께 10초가 지나도 소리가 계속 나고 알람을 끄면 다음 세트로 넘어간다는 확인을 받았다. 진동은 사용자 요청으로 제품 범위에서 제외했고, 화면 꺼짐 방지는 문제없을 것으로 판단했다. 소리 출력·반복 지속·수동 종료 후 진행은 확인 결과로 기록한다. 진동은 구현·검수 대상에서 제외하며 화면 꺼짐 방지의 장시간·OFF 비교와 잠금·복귀 등 다른 항목은 미확인이다.
- 동작: 휴식이 자연 만료되면 `휴식이 끝났어요` 화면에 다음 운동·세트와 `휴식 알람 끄기`를 표시한다. 두 신호를 1.2초 주기로 반복하며 확인 전 Tempo·수행 완료·타이머 시작을 대기한다. 확인은 수행 합계를 변경하지 않는다. 종료음 OFF·Player 음소거·수동 휴식 건너뛰기는 확인 화면 없이 진행한다.
- 저장·복귀: 세션에 boolean `restAlarmPending`을 저장한다. 이전 version 2에서 필드가 없으면 false로 취급해 이어하기를 유지한다. 새로고침 후 미확인 알람은 복구하고 확인한 알람은 다시 울리지 않는다. 숨김·대화상자·오디오 중단 때 소리를 멈추며 복귀하면 미확인 알람을 재개한다. 기기 잠금 중 백그라운드 재생은 보장하지 않는다.
- 코드: `apps/web/src/core/session.js`의 대기·해제·검증, `apps/web/src/browser/effects.js`의 반복 예약·정리, `apps/web/src/ui/views.js`의 확인 화면·이어하기 설명과 `apps/web/src/main.js`의 연결을 수정했다. 사용자 요청에 따라 진동 설정과 휴식 종료 진동 호출은 제품 흐름에서 제거했다.
- 검증: GAS 테스트를 제외한 핵심 로직 63개가 통과했다. `pnpm test:effects`에서 관련 로직 17개·브라우저 시나리오 17개가 통과했다. 기존 로컬 종합 시나리오 12개와 다섯 화면 크기의 전체 흐름 15개도 통과했다. 반복·수동 종료·음소거·Tempo 대기·수행 합계·기존 저장 형식·새로고침·복귀·시간 운동·버튼 접근을 확인했다.
- 범위 변경 검증: 진동 설정·호출을 제품 화면과 운동 흐름에서 제외한 뒤 `pnpm test:mobile`을 다시 실행해 핵심 로직 65개, 기존 브라우저 시나리오 12개, 모바일 화면·전체 흐름 15개가 통과했다.
- 화면: 360px 확인 화면과 844×390 가로 화면의 알람 끄기 버튼·다음 대상 안내 PNG를 직접 확인했다. 가로 화면에서는 스크롤로 48px 이상의 주 버튼에 접근한다.
- 공유 제약: 후속 현황 점검에서 기존 임시 주소의 DNS 만료와 `Unauthorized: Tunnel not found`를 확인했다. 자동 승인 검토가 터널 재생성 명령을 `blocked by policy`로 거부했다. 이전 터널 종료·새 터널 생성은 실행되지 않았으며 기존 로컬 서버는 유지된다. 새 외부 HTTPS 주소를 만들었다고 표시하지 않는다.
- 로컬 공유: 같은 Wi-Fi에서 확인할 별도 서버를 `0.0.0.0:4177`로 실행했다. PC의 `http://192.168.68.54:4177`에서 앱 로딩·알람 반복·터치 종료와 비공개 경로 404를 검증했다. 휴대폰이 같은 Wi-Fi인지 질문했으며 실제 휴대폰의 접속은 미확인이다. 서버의 exec 세션은 8193이고 주소는 `test-results/stage11/lan-preview-url.txt`에 기록한다.
- HTTP 보완: 로컬 네트워크의 비보안 컨텍스트에서 `crypto.randomUUID` 미지원으로 운동 시작이 실패하는 문제를 재현했다. `apps/web/src/browser/session-id.js`에서 native UUID를 우선 사용하고 미지원 시 `crypto.getRandomValues`의 16바이트로 ID를 생성하도록 보완했다. 해당 로직 2개와 실제 LAN HTTP의 운동 시작·반복 알람·수동 종료가 통과했다. 새 공유 주소에는 이전 주소의 휴대폰 저장값이 자동으로 적용되지 않는다. 로컬 HTTP의 Wake Lock 미지원도 확인했으며 이를 실기기 실패나 성공으로 판단하지 않는다.
- 후속 처리: 사용자가 남은 휴대폰 검수를 보류하고 12단계 진행을 요청했다. 시간 운동·잠금·Chrome 종료·아이콘 등 미확인 항목은 13단계 실제 배포 후 검수로 이관하며 통과로 표시하지 않는다. 진동은 제품 범위에서 제외했다.

### 앞선 음량 피드백 반영

- 확인된 결과: 사용자가 휴대폰 볼륨 50%에서 Tempo가 거의 들리지 않고 휴식 종료 알람도 매우 작다고 보고했다. 휴대폰 기종·OS·Chrome 버전과 다른 검수 항목의 성공 여부는 확인하지 않았다. 해당 조건의 가청 검수는 문제 있음으로 기록한다.
- 수정: 기존 최고 gain 0.12에서 바로 감소하던 소리를 Tempo 0.4·카운트 0.45·휴식 종료 0.55로 조정했다. Tempo는 80ms에서 160ms, 카운트는 80ms에서 180ms로 늘리고 일정한 음량을 유지한 후 짧게 줄여 종료한다. 휴식 종료는 250ms 신호 두 번으로 구분한다. 숫자는 Web Audio 출력 설정이며 휴대폰에서 체감 음량이 몇 배 증가했다는 뜻은 아니다.
- 제어: 휴식 종료 신호와 Tempo가 겹쳐도 설정된 peak gain의 합은 0.95다. Tempo가 꺼진 상태에서도 Player 음소거·대화상자·숨김·전체 종료 때 예약된 신호를 정리하도록 `apps/web/src/main.js`를 보완했다. 사용자 설정·세션 저장 형식은 바꾸지 않았다.
- 재검수: 같은 HTTPS 미리보기 페이지를 새로고침하고 휴대폰 볼륨 50%에서 Tempo·카운트·휴식 종료 신호를 다시 확인해야 한다. 물리적 출력 개선 여부는 아직 확정하지 않는다. 11단계와 GAS 대기 범위를 유지한다.
- 관련 검증: `pnpm test:effects`에서 로직 10개·Edge 헤드리스 브라우저 시나리오 13개가 통과했다. 실제 AudioParam의 출력 수준·유지·0으로 종료와 Tempo 단계 간격, 휴식 종료의 두 신호·간격·예약 유지, 옵션 OFF와 Tempo OFF 상태의 음소거에 따른 신호 취소를 확인했다. JavaScript·HTTP 오류가 없었다.

## 앞선 7·8단계 — 시간 운동과 이어하기 기록

## 검증

- 핵심 로직 테스트 22개 통과: 선택 순서, 설정 우선순위·중첩 복사·버전 처리, 전체 진행·완료·건너뛰기, 연속 이벤트, 타이머 복구·일시정지, 저장소 손상·실패.
- Edge 헤드리스에서 로컬 앱 브라우저 시나리오 12개 통과.
- 같은 12개 시나리오가 GAS로 묶은 클라이언트의 로컬 미리보기에서도 통과했다.
- 360·390·412px, 844×390 가로 화면, 1280×900 데스크톱에서 가로 넘침과 대화상자 포커스 이동을 자동 확인했다. 홈·운동·좁은 편집 대화상자 PNG를 직접 확인해 한국어 어절 줄바꿈을 보완했다.

- 초기 브라우저 검수에서 폼의 `name="id"`가 폼 `id`를 가리는 제출 오류를 발견해 수정하고 모든 시나리오를 재검증했다.
- 개발 의존성: esbuild 0.28.2, Playwright 1.63.0. pnpm lockfile과 esbuild의 제한된 설치 스크립트 허용 설정을 보관한다.
- 빌드 산출물 구조·서버/클라이언트 구문·manifest 검증까지 포함한 Node 테스트 23개가 통과했다. GAS 미리보기의 브라우저 요청은 HTML 하나뿐이며 별도 로컬 JS·CSS·이미지 요청과 HTTP 오류가 없음을 확인했다.
- AudioContext가 중단되면 활성화 버튼을 다시 표시하도록 보완하고 중단·사용자 클릭 후 재개도 검사했다. 최종 소스로 Node 23개, 로컬·GAS 미리보기 브라우저 시나리오 각 12개가 모두 통과했다.
